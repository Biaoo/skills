# DeepSeek Harness Review

Use this skill when important changes warrant an independent second opinion from a different model family via local DeepSeek Harness (`dsh`), locked strictly to read-only inspection.

> Cross-model review breaks confirmation bias only when it sees the real intent, cannot mutate the working tree, and reports substantiated material risks rather than style noise.

## When to Invoke vs. Skip

Invoke `dsh-review` for high-value gates:
- Core business logic, state machines, concurrency, auth/permissions, or data migrations.
- Multi-file refactors or non-trivial code generated by another agent (e.g., after `codex-delegate`).
- Pre-merge or pre-release sanity checks.

Skip `dsh-review` for:
- Trivial config edits, typo fixes, formatting, or single-file documentation updates.

## Strict Read-Only Contract

Requires `dsh >= 0.2` (check `dsh --profile headless --help` if flags differ on your version):

1. **Always run inside the target repo root**: `dsh` binds `workspaceRoot` in its sandbox policy from `process.cwd()`. Change directory into `$REPO` before invoking `dsh`.
2. **Always pass BOTH flags together**:
   `--permission-mode read-only --approval-policy never`
   The `read-only` preset defaults to `approval: ask`; omitting `--approval-policy never` can stall headless runs.
3. **Never inspect or print credentials**: do not read or echo `~/.dsh/.credentials.yaml`, `DEEPSEEK_API_KEY`, or profile secret overlays.
4. **Hard mutation guard**: snapshot `git status --porcelain` before and after running `dsh`. If anything changed, treat it as a sandbox breach and alert the user immediately.

## Review Packet Contract

Never feed a naked `git diff`. Pack the prompt in **static-first, dynamic-last** order so the shared review prefix stays cache-friendly:

1. **Strict Output & Focus Rules (static top)**:
   - Reviewer role and strict read-only rule.
   - Focus only on correctness, broken requirements, security/auth flaws, concurrency/lifecycle bugs, silent config shadowing, and unnecessary complexity (YAGNI). Do not report formatting, naming taste, or speculative nits.
   - Require exact evidence (`path:line`, failure scenario, minimal fix direction) and a single top-level verdict: `VERDICT: SHIP | SHIP_WITH_NOTES | BLOCK`.
2. **Intent & Acceptance Criteria (dynamic)**: 1 concise paragraph explaining what the change is supposed to achieve and any critical invariants.
3. **Change Summary (`git diff --stat`)**: quick map of affected files.
4. **Diff Payload**: `git diff` (or file paths + focused slices if the diff is too large to inline cleanly).

## Shell Execution Patterns

Run `dsh --profile headless` as a foreground process in the coordinator's shell tool (never append `&` or `nohup`) so the host tracks completion and wakes up automatically with the real exit code and review report.

### Review Uncommitted Changes (Staged + Working Tree)

```bash
REPO="/path/to/repo"
PROMPT=$(mktemp /tmp/dsh-review.XXXXXX)
BEFORE=$(git -C "$REPO" status --porcelain)

{
  cat <<'EOF'
You are an independent, strictly READ-ONLY code reviewer.
Do NOT edit, write, or create any files. Inspect repository context as needed and review only against the intent and diff below.

Focus strictly on:
- Correctness, regressions, and unmet requirements
- Security, auth boundaries, and secret safety
- Concurrency, lifecycle, error handling, and config shadowing
- Unnecessary complexity or abstractions (YAGNI)
Skip style nitpicks.

Required output format:
VERDICT: SHIP | SHIP_WITH_NOTES | BLOCK
Findings (ordered Blocker -> High -> Medium; omit section if none):
- [Severity] path:line — concrete failure scenario and minimal fix direction

--- Task Context ---
Intent & Acceptance Criteria:
<1-paragraph summary of requirements and invariants>

--- git diff --stat ---
EOF
  git -C "$REPO" diff HEAD --stat
  echo ""
  echo "--- git diff HEAD ---"
  git -C "$REPO" diff HEAD
} > "$PROMPT"

(cd "$REPO" && dsh --profile headless --permission-mode read-only --approval-policy never -) < "$PROMPT"
STATUS=$?

AFTER=$(git -C "$REPO" status --porcelain)
if [ "$BEFORE" != "$AFTER" ]; then
  echo "ERROR: working tree changed during read-only review" >&2
  STATUS=1
fi
rm -f "$PROMPT"
exit "$STATUS"
```

### Useful Variants

- **Staged changes only**: replace `git diff HEAD` with `git diff --cached`.
- **Branch / PR diff against base**: replace `git diff HEAD` with `git diff main...HEAD`.
- **Structured run events**: add `--json` after `headless` when wrapping in automation.
- **Interactive visual review fallback**: if a diff is huge and the user wants a GUI to annotate lines interactively, suggest launching `(cd "$REPO" && dsh web)` and opening its Code Review page.

## Prompt Cache & Session Reuse

- **Static prefix first**: keep the fixed reviewer role, rubric, and output format above variable intent and diffs; never insert timestamps, random IDs, or temp paths before static instructions.
- **Canonical repo root & stable flags**: always run from the same canonical `$REPO` root with the same `--profile headless --permission-mode read-only --approval-policy never` flags, without toggling plugins or MCP servers between runs, to maximize DeepSeek prefix context-cache hits.
- **Incremental re-review with `--session-id`**: keep 1 automated round as the default; if the user explicitly asks for a follow-up re-check of fixes on the same change, reuse `--session-id <id>` from the same `$REPO` root and send only the incremental diff.

## Triage and Convergence

1. **Max 1 automated review round by default**: avoid back-and-forth ping-pong loops between the writer agent and reviewer agent.
2. **Verify before reporting**: check every `Blocker` / `High` finding against actual source files to filter false positives or context misunderstandings.
3. **Escalate cleanly**: present the verified findings, verdict, and recommended action (`ship as-is`, `targeted local fix`, or `delegate fix via codex-delegate`) for user sign-off.
